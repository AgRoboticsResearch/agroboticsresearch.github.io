02 / Data contract

One visual observation. One compact action.

The final release intentionally keeps only what the learning pipeline consumes. Stereo is crucial upstream for trajectory recovery, but it is not duplicated into the training observation.

Observation

First-person RGB

The D405 color stream, encoded as AV1 video and exposed as observation.images.camera.

video · [480, 640, 3] · 30 fps
Action

Next-frame EE target

Camera-trajectory position and rotation vector, stored under the EE-labelled schema, plus normalized gripper opening. The final frame repeats its own target.

[ ee.x, ee.y, ee.z, ee.wx, ee.wy, ee.wz, ee.gripper_pos ]
Important metadata details: robot_type: so100 is a compatibility label written by the converter. These are handheld SROI demonstrations, not SO-100 joint-teleoperation logs. The ee.* names are also a learning-schema convention: the converter writes the transformed D405 camera pose directly to those fields. Camera-to-gripper-tip extrinsics are used for projection QC, not baked into the released action. No joint state is released, and observation.state is intentionally omitted.

03 / Source to release

Three recorded streams become one learning sample.

The raw tree and the LeRobot tree serve different jobs. Raw MP4 and decoded PNG data preserve the evidence needed to estimate motion; the released dataset packages only RGB plus action.

01 · CAPTURE

Direct RealSense recording

D405 left IR, right IR, and color at 640 × 480 / 30 fps. Current Pi capture uses pyrealsense2, not ROS bags.

02 · DECODE

Regenerable PNG tree

MP4 sessions are decoded into a separate working tree. The raw compressed recordings remain unchanged.

03 · ESTIMATE

Masked stereo SLAM

The visible gripper is masked from both IR views before ORB-SLAM3 estimates the camera trajectory.

04 · ALIGN

Pose + gripper

Trajectory axes are converted; AprilTags in the color stream recover a normalized gripper signal.

05 · RELEASE

QC + LeRobot

Accepted episodes become AV1 RGB observations, Parquet actions, episode metadata, and statistics.

06 / On disk

The final tree is small and conventional.

Parquet carries actions and index fields; MP4 carries RGB observations; metadata describes features, per-episode ranges, tasks, and aggregate statistics.

sroiv2_strawberry_picking_lab_1459_occlusion/
├── data/chunk-000/file-000.parquet            # frame records + 7-D action
├── videos/observation.images.camera/
│   └── chunk-000/file-000.mp4 … file-012.mp4  # AV1 RGB
└── meta/
    ├── info.json                                  # schema + counts + paths
    ├── stats.json                                 # aggregate statistics
    ├── tasks.parquet                              # task vocabulary
    └── episodes/chunk-000/file-000.parquet        # 1,459 rows
Reproducibility boundary: the public LeRobot tree is the training artifact. To regenerate trajectories or change masking, calibration, gripper normalization, or QC criteria, return to the raw recordings and the processing repository.
07 / Historical release

SROI V1 remains available as ROS bags.

Use the Zenodo archive when your work depends on the original multi-camera field recordings or ROS topics. It is a different release format and should not be confused with the V2 LeRobot pair above.

Original field dataset, preserved.

V1 was collected at two strawberry farms from December 2024 to January 2025. It includes OAK-D-SR and RealSense D435i configurations, stereo imagery, IMU data, camera calibration, and action-segmentation status in ROS bags.
